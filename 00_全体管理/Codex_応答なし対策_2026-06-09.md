# Codex 応答なし対策メモ 2026-06-09

## 起きていたこと

- Codex の処理前準備で `sandbox setup refresh failed` が再発。
- `git status` に大量の未追跡ファイルが出ており、生成画像・音声・YouTube 生データが主な負荷になっていた。
- 特に `reel_assets/bone_density_series/` と `SNS-OS/analytics/raw/` が増えていた。

## 原因候補

- F ドライブの ANRYCAMPANY 全体を作業場所にしているため、Git と Codex の確認対象が広い。
- 動画素材、音声、背景画像、確認用フレームなどの生成物が Git の未追跡ファイルとして大量に出ていた。
- その結果、Codex 側のサンドボックス準備や状態確認で詰まりやすくなっていた。

## 今回行った対策

- `.gitignore` に次を追加し、生成物と生データを Git の通常確認対象から外した。
  - `SNS-OS/analytics/raw/`
  - `reel_assets/bone_density_series/`
  - `_video_work` 系
  - `audio` 系
  - `background_frames`
  - `final_text_frames`
  - `generated_backgrounds`
  - `sample_review_frames`
- Git の軽量化設定を有効化した。
  - `core.untrackedCache=true`
  - `core.fscache=true`

## 残っている注意点

- 既存の未保存変更は多い。今回、それらは削除・巻き戻ししていない。
- 登録キャラクター素材や台本・投稿メモは、生成作業の重要素材なので除外していない。
- 今後も新しい動画シリーズで大量の画像・音声が増えたら、シリーズ単位で `.gitignore` に追加する。

## 今後の運用

- 完成品・台本・投稿情報・管理CSVは残す。
- 作業中の画像、音声、フレーム、バックアップ、確認用素材は原則 Git に入れない。
- Codex が重い時は、まず `git status --short` の未追跡ファイル量を確認する。
