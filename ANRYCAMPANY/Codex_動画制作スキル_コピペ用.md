# Codex_動画制作スキル_コピペ用

動画制作を始める時は、長いルールを貼らない。
細かいルールは `AGENTS.md`、スキル、`00_全体管理/rules/` 側でCodexが読む。

このノートでは、毎回貼る文を短くする。
ただし、次の2つは運用で使うため消さない。

- `投稿情報を登録する時`
- `分析・解析`

週次分析後は、承認済みの改善点だけを `$anry-video-from-user-plan` の `latest-weekly-improvements.md` に3〜5個で反映する。
長い分析本文やKPI原文は毎回読ませない。
週次分析結果は `ANRYCAMPANY/YouTube分析/YYYY-MM-DD_YYYY-MM-DD_週次分析.md` に残す。
次に作る動画候補を出す時は、必ず `ANRYCAMPANY/投稿情報/投稿情報_一覧.md` と `ANRYCAMPANY/01_動画管理.md` を確認する。
新規案は、既存投稿と同じ主語・同じ不安・同じ検査場面を避ける。
2026年11月以降の週次提案は、原則として `3か月以上前の高再生作品のリメイク1本`、`3か月以上前の低再生作品のリメイク1本`、`完全新規1本` の3枠に分ける。リメイクと新規を混同せず、元作品と変更点を明記する。

## 使い分け

- Claude Code: 台本初稿、構成のたたき台。
- GPT-5.6: KPI確認、過去投稿との照合、軽量な改善案。
- GPT-5.5: 医療表現、誤解リスク、不安を煽らないかの最終確認。
- `$anry-video-production`: テーマからCodexに台本案・投稿情報案・画像構成案を提案してほしい時。
- `$anry-video-from-user-plan`: 台本案・画像構成案・キャラ案などをこちらで用意している時。

## テロップ文言を指定したい時

```text
画像OKです。次はテロップ作成に進んでください。

以下のルールを厳守してください。

### 1. テロップ内容

- 音声全文を書き起こさず、要点だけを表示する。  
- 1画面1メッセージ。   
- 原則15文字以内、最大20文字を目安とする。   
- 原則1行、必要な場合のみ最大2行。   
- 患者さんに伝わる、やさしく簡潔な表現にする。   
- 医療情報は断定しすぎず、正確さを優先する。  
- 重要語のみ強調し、青強調も単語単位に限定する。    
- 文字数が多い場合は文章を短縮し、安易に文字を小さくしない。    

### 2. テロップ位置

- 全フレーム、X座標は必ず画面中央に固定する。    
- Y座標も原則として画面中央に統一する。    
- 人物の頭・顔・髪に重なる場合のみ、上中央または下中央へ変更する。    
- 上・中央・下は、それぞれ共通の固定位置を使用する。    
- 余白に合わせて左右へ移動させない。    
- フレームごとに自由な位置調整をしない。    

### 3. 作成・確認

- 承認済み画像を変更しない。    
- 文字数・行数・配置位置を全フレームで確認する。    
- 医療的な意味が変わる省略はしない。    
- 長文を解消できない場合は、勝手にフレームを増やさず相談する。    
- テロップ案を提示し、承認を受けるまで音声・動画生成に進まない。
  
### 4. テロップの文字サイズ・視認性

- テロップはスマートフォンでの視認性を最優先する。    
- 縦型動画（1080×1920）では、フォントサイズを原則64pxとする。    
- 横型動画（1920×1080）では、フォントサイズを原則56pxとする。    
- 全フレームで基本フォントサイズを統一する。    
- 文字数に応じて自動的にフォントサイズを縮小しない。    
- 文字が収まらない場合は、まず文章を短縮し、必要に応じて2行にする。    
- 文字には適切な縁取りや影を付け、背景に埋もれないようにする。    
- 完成イメージを実際の動画解像度で確認し、スマートフォンでも読みやすい大きさになっているか検証する。
```

## 音声・動画に進む時

```text
画像とテロップOKです。
音声と動画生成に進んでください。

【VOICEVOX音声】

- 話者は「もち子さん」で統一する。
- VOICEVOXの音声生成時に話速（speedScale）を1.15に設定する。
- 動画編集で追加の倍速処理をしない。
- 患者さんに説明するような、自然で落ち着いた話し方にする。
- 文末や意味の区切りには、自然な間を残す。
- 不自然に長い無音だけを取り除き、必要な間は削らない。
- 抑揚やアクセントを調整し、機械的な棒読みを軽減する。
- 医療用語は特に聞き取りやすさを優先する。

【動画の確認】

- 音声と画像・テロップのタイミングを合わせる。
- シーン間に不自然な無音を作らず、音声の途中切れや重なりを防ぐ。
- 音声を詰め込むために、無理に間を短縮しない。
- 必要であれば各シーンの表示時間を調整する。
- 完成動画を通して確認し、早口や不自然な間がないか確認する。

今回は音声の自然さと聞き取りやすさを最優先してください。
```

# 週次分析・動画改善・次週企画選定

## 目的

InstagramとYouTubeの週次データを分析し、次週の動画制作に直結する改善策を抽出する。

**最終目標は週3本の企画選定。**

- 高再生作品のリメイク：1本    
- 低再生作品のリメイク：1本    
- 完全新規：1本    

ただし、CodexとClaudeの独立提案を比較する前に最終決定しない。

## 1. 分析対象

**Instagram**

Obsidian内の以下のデータを確認する。

`インスタ_週次結果metricool「20261101」`

**YouTube**

`F:\ANRYCAMPANY\ANRYCAMPANY\YouTube分析\02_週別データ\「2026-10-24_2026-10-31」`

さらに以下を確認する。

- 過去の週次分析    
- 投稿情報一覧    
- 動画管理    
- 公開済み・予約済み作品    
- 前週の `latest-weekly-improvements.md`    

集計期間は各データの実際の開始日・終了日を確認し、InstagramとYouTubeを混同しない。

確認できないファイルや指標は推測で補わず、「未確認」と明記する。

## 2. 週次パフォーマンス分析

以下を分析する。

1. 伸びた動画と伸びた理由    
2. 伸びなかった動画と考えられる原因    
3. 冒頭3秒の改善点    
4. 保存・シェアされやすいテーマ    
5. CTAの改善点    
6. 次週も使う構成・表現    
7. やめる、または改善する構成・表現    

### 評価上の注意

- 再生回数だけで成功・失敗を判断しない。    
- Instagramではリーチ、保存率、シェア率などを利用可能な範囲で評価する。 
- YouTubeでは視聴継続率、平均視聴時間、平均再生率などを確認する。    
- 公開からの経過時間が異なる作品を、単純な累計再生数で比較しない。    
- 可能なら公開後7日間など、同じ観測期間で比較する。    
- 指標の定義や取得条件が違う場合は、無理に比較しない。    
- 冒頭3秒の映像や維持率データがない場合、実際の映像を確認したような評価をしない。    
- データから確認できる事実と、改善のための仮説を分ける。    
- 1本だけの結果で制作ルールを断定しない。    

各改善案には、根拠となる作品名・指標・具体的な変更内容を示す。

## 3. 視聴者目線の企画リサーチ

必要に応じて以下を調査する。

- X    
- 病院FAQ    
- 公的機関・医療機関の説明    
- Google検索・関連質問    
- その他SNS・別プラットフォーム    

特にXでは、患者さんや家族が日常的に使う疑問や不安の言葉を調べる。

優先するテーマ：

- 服装、下着、アクセサリー    
- 日用品、持ち物    
- 検査当日の行動    
- 検査前後の迷い    
- 家族・付き添いの困りごと    
- 医療者が見落としやすい生活上の疑問    

単発投稿だけで需要を判断しない。

複数の独立した情報源に共通する疑問や不安を優先する。

**XやSNSは企画需要と患者さんの言葉を調べるために使用し、医学的根拠には使用しない。**

医学的な事実は病院・公的機関・信頼できる医学情報で確認し、参照元を残す。

検索結果で需要を確認できなかった場合は、確認できなかったことを明記する。

## 4. リメイク候補の抽出

基準日から3か月以上前に公開された作品だけを対象とする。

高再生候補と低再生候補を分けて抽出する。

各作品について以下を記載する。

- 元作品の公開日    
- 正式タイトル    
- 視聴回数    
- 観測期間    
- 高再生・低再生と判定した根拠    
- リメイクする理由    
- 元作品から変える冒頭3秒    
- 構成の変更点    
- CTAの変更点    
- 画像・テロップなど画面表現の変更点    

低再生候補は、病院FAQ、検索結果、他SNS、別プラットフォームなどで題材の需要を確認できたものに限定する。

需要が確認できない場合は無理に低再生リメイクを提案しない。

同じ経過日数での視聴回数が取得できない場合は比較不可とし、確認できる数値と取得条件だけを記載する。

## 5. 完全新規候補の抽出

投稿情報一覧と動画管理の両方を確認する。

公開済みだけでなく、予約済み・制作中の作品も対象とする。

次の4項目で重複を確認する。

1. 主語・対象者    
2. 患者さんの疑問や不安    
3. 検査場面    
4. 動画の主な結論    

タイトルが異なっても、実質的に同じ内容なら重複扱いとする。

新規候補には、患者さんが実際に検索しそうな疑問形のタイトルを優先する。

過去作品との違いと需要の根拠を記載する。

リメイク枠と完全新規枠を混同しない。

## 6. Codexによる一次提案

以下の3枠を独立して提案する。

- 高再生リメイク    
- 低再生リメイク    
- 完全新規    

各枠について候補を原則2本以上挙げ、根拠を記載する。

ただし、条件を満たす候補が不足する場合は無理に増やさない。

各候補に、検索されやすいタイトル案、冒頭3秒、構成、CTA、画面表現を付ける。

この段階では最終3本を確定しない。

## 7. Claudeへの情報共有

Claudeはローカルフォルダを直接確認できない前提とする。

Claudeへ渡す情報共有プロンプトを作成する。

必須内容：

- 3か月以上前の高再生・低再生リメイク候補一覧（公開日・正式タイトル・比較可能な期間の視聴回数）    
- 投稿済み作品の題材一覧    
- 予約済み・制作中作品の題材一覧    
- 重複判定ルール    
- 患者さんの疑問・不安についての外部リサーチ結果と情報源    

**ClaudeにはCodexの採用案・候補順位・推奨理由を見せない。**

Claudeにも、高再生リメイク・低再生リメイク・完全新規を独立して提案してもらう。

データが長い場合でも、判断に必要な作品情報を省略しない。

## 8. 最終企画選定

Claudeの回答を受け取った後に実施する。

Codex案とClaude案を統合し、重複を整理して6〜10本程度の候補プールを作る。

候補が不足する場合は数合わせをしない。

次の観点で比較する。

- 患者さんの実際の需要    
- 過去作品との重複の少なさ    
- 冒頭3秒の訴求力    
- 医学的な正確性    
- 制作の実現性    
- 今週の分析結果との整合性    

一次情報を確認したうえで、各枠1本、計3本を最終提案する。

Claudeの回答が未提供の場合は、ここで停止し、最終決定済みとしない。

**スキル更新は、提案内容の確認後に実施する。**

## 分析してほしい点

### 1. チャンネル全体の発見経路

- Shortsフィードからの流入割合
- YouTube検索からの流入
- チャンネルページからの流入
- その他の流入元
- 前月と比べて発見経路に変化があるか

Shortsフィード依存が強まっているのか、検索やチャンネルページなど別の経路が育っているのかを確認してください。

### 2. 新しい視聴者とリピーター

- 新しい視聴者数
- ユニーク視聴者数
- リピーター数
- 前月からの変化

新規流入が中心なのか、繰り返し見てくれる視聴者が育っているのかを確認してください。
単月だけで断定せず、可能であれば過去2〜3か月の傾向も確認してください。

### 3. YouTube検索

YouTube検索からの流入が、

- 増えている
- 横ばい
- 減っている

のどれに近いか確認してください。

患者さんや家族の疑問に答える動画が、Shortsフィードだけでなく検索から継続的に見つかる状態へ近づいているかを重視してください。
検索流入に明確な変化がある場合は、どのテーマや動画が影響している可能性があるかも確認してください。

### 4. 視聴者属性

以下について前月からの変化を確認してください。

- 年齢
- 性別
- 地域

数値の小さな変動を過大評価せず、明確な変化がある場合だけ取り上げてください。
現在想定している視聴者と、実際に届いている視聴者にズレがないかも確認してください。

### 5. 視聴環境

- スマートフォン
- タブレット
- PC
- テレビ
- その他

どのデバイスから視聴されているかを確認してください。
また、

- Shortsフィード
- チャンネルページ
- その他の再生場所

についても確認し、現在の動画形式と視聴環境が合っているか分析してください。

### 6. コンテンツ構成

- Shorts
- 通常動画
- ライブ
- その他

の比率を確認してください。
現在のチャンネルが実質的にどのコンテンツ形式へ依存しているかを確認し、現状の運用とズレがないか見てください。

### 7. 前月比較

月次分析では、可能な限り前月と比較してください。

特に、

- Shortsフィード依存度
- YouTube検索
- 新しい視聴者
- ユニーク視聴者
- リピーター
- 視聴者属性

について、前月から明確な変化があるものを優先して説明してください。
可能であれば3か月程度の流れも確認し、一時的な変動と継続的な傾向を分けてください。

## 週次分析との関係

週次分析で出した改善策について、月次データから見ても方向性が合っているか確認してください。
ただし、個別動画の細かな改善は週次分析に任せ、月次分析ではチャンネル全体の方向性に影響するものだけ取り上げてください。

1. 今月のチャンネル全体サマリー

3. Shortsフィード依存度

分析結果はObsidianの月次分析ノートにも残してください。

## 使い方のコツ

- 依頼文にルールを長く書かない。
- テーマ、対象ノート、素材フォルダ、今進めたい工程だけを書く。
- 台本全文を毎回貼り直さず、承認済みノートや素材フォルダを指定する。
- 画像、音声、動画へ進む時は「何がOK済みか」を短く書く。
- 人物が出る時は、Character全文ではなく `_character_quickref.md` と `_patient_clothing_index.md` を優先する。
- 投稿情報登録と分析・解析のコピペ欄は、運用に必要なので消さない。
- 台本確認で冒頭・保存・CTAを見る時は、最新の週次改善メモも確認させる。
- 次候補を出す時は、既存投稿・予約済み投稿と被らないかを先に確認させる。
- Claudeへ共有する時は、Claudeがローカルフォルダを見られない前提で、必要な既存タイトル一覧と週次改善点をプロンプト本文に直接貼る。
- テロップで重要語だけ色を変える時は、生成前に「強調語だけが別セグメントか」を確認させる。`any(key in part for key in highlights)` のような包含判定だと、語を含む文節全体が青になる。
- 修正版のテロップや画像は、前回フォルダに混ぜず日付つきの専用フォルダに出力させる。
