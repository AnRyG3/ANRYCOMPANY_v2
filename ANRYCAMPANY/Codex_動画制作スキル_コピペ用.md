# Codex_動画制作スキル_コピペ用

動画制作を始める時は、長いルールを貼らない。
細かいルールは `AGENTS.md`、スキル、`00_全体管理/rules/` 側でCodexが読む。

このノートでは、毎回貼る文を短くする。
ただし、次の2つは運用で使うため消さない。

- `投稿情報を登録する時`
- `分析・解析`

週次分析後は、承認済みの改善点だけを `$anry-video-from-user-plan` の `latest-weekly-improvements.md` に3〜5個で反映する。
長い分析本文やKPI原文は毎回読ませない。
週次分析結果は `ANRYCAMPANY/YouTube分析/YYYY-MM-DD_YYYY-MM-DD_週次分析.md` に残す。
次に作る動画候補を出す時は、必ず `ANRYCAMPANY/投稿情報/投稿情報_一覧.md` と `ANRYCAMPANY/01_動画管理.md` を確認する。
新規案は、既存投稿と同じ主語・同じ不安・同じ検査場面を避ける。
2026年11月以降の週次提案は、原則として `3か月以上前の高再生作品のリメイク1本`、`3か月以上前の低再生作品のリメイク1本`、`完全新規1本` の3枠に分ける。リメイクと新規を混同せず、元作品と変更点を明記する。

## 使い分け

- Claude Code: 台本初稿、構成のたたき台。
- GPT-5.6: KPI確認、過去投稿との照合、軽量な改善案。
- GPT-5.5: 医療表現、誤解リスク、不安を煽らないかの最終確認。
- `$anry-video-production`: テーマからCodexに台本案・投稿情報案・画像構成案を提案してほしい時。
- `$anry-video-from-user-plan`: 台本案・画像構成案・キャラ案などをこちらで用意している時。

```text

まず台本案・投稿情報案・画像構成案だけ出してください。
まだ画像・音声・動画は作らないでください。
```

```

## キャラクターが出る時

$anry-video-from-user-plan で確認してください。

まだ画像・音声・動画は作らないでください。

【ここに台本案・画像構成案を貼る】
```

## 画像に進む時

```text
承認済みの内容で、画像計画と1〜2枚の確認用フレームに進んでください。
まだ残り画像・テロップ・音声・動画は作らないでください。
```

## 残り画像に進む時

```text
確認用フレームOKです。
残りの画像に進んでください。
まだテロップ・音声・動画は作らないでください。
```

## テロップに進む時

```text
画像OKです。テロップ入力に進んでください。
テロップは要点だけにして、1画面あたり短く読みやすくしてください。
まだ音声・動画は作らないでください。
```

## テロップ文言を指定したい時

```text
画像OKです。次はテロップ作成に進んでください。

以下のルールを厳守してください。

### 1. テロップ内容

- 音声全文を書き起こさず、要点だけを表示する。  
- 1画面1メッセージ。   
- 原則15文字以内、最大20文字を目安とする。   
- 原則1行、必要な場合のみ最大2行。   
- 患者さんに伝わる、やさしく簡潔な表現にする。   
- 医療情報は断定しすぎず、正確さを優先する。  
- 重要語のみ強調し、青強調も単語単位に限定する。    
- 文字数が多い場合は文章を短縮し、安易に文字を小さくしない。    

### 2. テロップ位置

- 全フレーム、X座標は必ず画面中央に固定する。    
- Y座標も原則として画面中央に統一する。    
- 人物の頭・顔・髪に重なる場合のみ、上中央または下中央へ変更する。    
- 上・中央・下は、それぞれ共通の固定位置を使用する。    
- 余白に合わせて左右へ移動させない。    
- フレームごとに自由な位置調整をしない。    

### 3. 作成・確認

- 承認済み画像を変更しない。    
- 文字数・行数・配置位置を全フレームで確認する。    
- 医療的な意味が変わる省略はしない。    
- 長文を解消できない場合は、勝手にフレームを増やさず相談する。    
- テロップ案を提示し、承認を受けるまで音声・動画生成に進まない。
```

## 音声・動画に進む時

```text
画像とテロップOKです。
音声と動画生成に進んでください。
画像と音声が合っているか確認してください。
また、不自然な「間」はつくらないようにしてください。
```

## 動画完成後: タイトル・説明・ハッシュタグ

```text
動画完成です。
タイトル、説明文、ハッシュタグをお願いします。
投稿メタ情報やハッシュタグに #ANRYCAMPANY は入れないでください。
説明文の後に、「音声：VOICEVOX:もち子さん(cv 明日葉よもぎ)」を必ず入れてください
```

## 途中から再開する時

```text
このリール制作を再開してください。
対象ノートまたは素材フォルダ: ここに貼る
次に必要な作業だけ提案してください。
```

## 投稿情報を登録する時

この項目は消さない。

```text
完成動画の投稿情報をObsidian vaultに登録してください。

**公開予約情報**

- 公開予定日：2026/10/31   
- 公開予定時刻：19:00    
- YouTube URL：    

**登録内容**

- 投稿タイトル    
- 説明文    
- ハッシュタグ    
- 公開予約日時    
- YouTube URL    

**日付のルール（厳守）**

- Obsidianのノート名・投稿日・管理上の日付には、必ず「公開予定日」を使用する。    
- 作業日（今日の日付）を投稿日として使用しない。    
- 公開予定日が指定されていない場合は、推測せず確認する。    
- 既存のObsidian vaultのフォーマットと保存先を維持する。    

**保存後の確認**

- ノート名と投稿日が公開予定日と一致しているか確認する。    
- 登録先のファイルパスと登録内容を報告する。
```

## 分析・解析

この項目は消さない。

```text
週次分析

Obsidianの該当週のInstagram/YouTube分析データを確認して、動画改善に直結する形で分析してください。

Instagramはインスタ_週次結果metricool「20261025」として入っています。  
YouTubeは `F:\ANRYCAMPANY\ANRYCAMPANY\YouTube分析\02_週別データ\「2026-10-17_2026-10-24」` に入っています。

MetricoolとYouTubeアナリティクスの集計期間が異なる場合は、混同せず別々に扱ってください。

見てほしい点:

- 伸びた動画   
- 伸びなかった動画  
- 冒頭3秒の改善点   
- 保存されやすいテーマ  
- CTAの改善点   
- 次も使う型   
- やめる型   
- 次に作る動画候補  
- 動画制作スキルの `latest-weekly-improvements.md` に反映すべき3〜5個の改善点   

次に作る動画は、次の3枠を各1本ずつ提案してください。

- 公開から3か月以上経過した高再生作品のリメイク
- 公開から3か月以上経過した低再生作品のリメイク
- 完全新規

リメイクは元作品の公開日・タイトル・比較可能な期間の視聴回数を示し、元作品から変える冒頭3秒、構成、CTA、画面表現を明記してください。低再生作品は、題材の需要を病院FAQ、検索結果、他SNSまたは別プラットフォームの反応で確認できる場合だけ候補にしてください。需要が確認できない作品を、低再生という理由だけで作り直さないでください。

完全新規は、投稿情報一覧と動画管理にある過去投稿・予約済み投稿と照合し、同じ主語、同じ不安、同じ検査場面の案を出さないでください。リメイク枠と完全新規枠を混同しないでください。

必要に応じて、X、病院FAQ、検索結果・関連質問、その他SNSなどもリサーチしてください。

特にXは医学的事実の根拠としてではなく、患者さんや家族が実際にどのような言葉で疑問や不安を表現しているかを把握するための企画リサーチとして使用してください。

Xでは、患者さんや家族の日常品、服装、アクセサリー、持ち物、検査当日の行動、検査前後の迷い、家族としての困りごとなど、医療従事者側では見落としやすいテーマを優先して確認してください。

単発の投稿だけを根拠に動画企画を作るのではなく、複数の投稿や検索結果で共通して見られる疑問・不安・迷いがある場合に、新しい動画候補として検討してください。

医学的な内容を判断する場合は、XやSNSの情報を根拠にせず、信頼できる医療情報や病院・公的機関等の情報で確認してください。

新しい動画候補では、「医療者が説明したい内容」だけでなく、「患者さんがスマートフォンで実際に検索したくなる疑問」を重視してください。

分析後、動画制作スキル更新用の短い改善メモ案も出してください。

最後に、分析結果をObsidianの週次分析ノートにも残してください。

Claudに情報共有するので、情報共有のプロンプトもお願いします。Claudはフォルダを見に行けないため、次の情報をプロンプト本文に含めてください。

- 3か月以上前の投稿について、公開日・タイトル・同じ観測期間の視聴回数を記したリメイク候補一覧
- 投稿済み・予約済みの題材一覧
- 今週のInstagramとYouTubeの分析要約。集計期間は分けて記載

ClaudにはCodexの採用案を見せず、高再生リメイク、低再生リメイク、完全新規を独立して提案してもらってください。Codex案とClaud案を合わせて6〜10本の候補プールにし、重複確認と一次情報確認後、実際の週3本として各枠1本を最終提案してください。
```


## 月次分析
```
YouTubeアナリティクスから取得した該当月の月次データを確認して、チャンネル全体の方向性を分析してください。  
データは　`F:\ANRYCAMPANY\ANRYCAMPANY\YouTube分析\00_月次分析\「2026-9月」`の中に入れてあります

月次分析の目的は、個別動画の勝ち負けではなく、

- 誰に届いているか
- どこから見つけられているか
- 新規視聴者が増えているか
- リピーターが育っているか
- Shortsフィード依存が強いか
- YouTube検索が伸びているか
- 視聴者属性がどう変化しているか
を確認し、翌月のチャンネル運用方針につなげることです。

週次分析では個別動画の改善を行っているため、月次分析では動画ごとの細かなランキングや勝ち負けを繰り返さず、チャンネル全体の構造変化を優先してください。

確認する月次データ:

- トラフィックソース
- 新しい視聴者
- ユニーク視聴者
- リピーター
- 視聴者の年齢
- 視聴者の性別
- 地域
- デバイスのタイプ
- YouTubeサービス
- コンテンツタイプ
- 再生場所
## 分析してほしい点

### 1. チャンネル全体の発見経路

- Shortsフィードからの流入割合
- YouTube検索からの流入
- チャンネルページからの流入
- その他の流入元
- 前月と比べて発見経路に変化があるか

Shortsフィード依存が強まっているのか、検索やチャンネルページなど別の経路が育っているのかを確認してください。

### 2. 新しい視聴者とリピーター

- 新しい視聴者数
- ユニーク視聴者数
- リピーター数
- 前月からの変化

新規流入が中心なのか、繰り返し見てくれる視聴者が育っているのかを確認してください。
単月だけで断定せず、可能であれば過去2〜3か月の傾向も確認してください。

### 3. YouTube検索

YouTube検索からの流入が、

- 増えている
- 横ばい
- 減っている

のどれに近いか確認してください。

患者さんや家族の疑問に答える動画が、Shortsフィードだけでなく検索から継続的に見つかる状態へ近づいているかを重視してください。
検索流入に明確な変化がある場合は、どのテーマや動画が影響している可能性があるかも確認してください。

### 4. 視聴者属性

以下について前月からの変化を確認してください。

- 年齢
- 性別
- 地域

数値の小さな変動を過大評価せず、明確な変化がある場合だけ取り上げてください。
現在想定している視聴者と、実際に届いている視聴者にズレがないかも確認してください。

### 5. 視聴環境

- スマートフォン
- タブレット
- PC
- テレビ
- その他

どのデバイスから視聴されているかを確認してください。
また、

- Shortsフィード
- チャンネルページ
- その他の再生場所

についても確認し、現在の動画形式と視聴環境が合っているか分析してください。

### 6. コンテンツ構成

- Shorts
- 通常動画
- ライブ
- その他

の比率を確認してください。
現在のチャンネルが実質的にどのコンテンツ形式へ依存しているかを確認し、現状の運用とズレがないか見てください。

### 7. 前月比較

月次分析では、可能な限り前月と比較してください。

特に、

- Shortsフィード依存度
- YouTube検索
- 新しい視聴者
- ユニーク視聴者
- リピーター
- 視聴者属性

について、前月から明確な変化があるものを優先して説明してください。
可能であれば3か月程度の流れも確認し、一時的な変動と継続的な傾向を分けてください。

## 週次分析との関係

週次分析で出した改善策について、月次データから見ても方向性が合っているか確認してください。
ただし、個別動画の細かな改善は週次分析に任せ、月次分析ではチャンネル全体の方向性に影響するものだけ取り上げてください。

3. Shortsフィード依存度

6. 視聴者属性の変化

数値が少ない、期間が短い、変化が小さい場合は無理に結論を出さず、「現時点では判断保留」としてください。

分析結果はObsidianの月次分析ノートにも残してください。

## 週次改善メモをスキルへ反映する時

```text
承認済みの週次改善メモで、$anry-video-from-user-plan の latest-weekly-improvements.md を更新してください。
Obsidianの動画制作スキルコピペ用ノートも必要なら更新してください。
古い改善点は残さず、今週使う3〜5個だけにしてください。
```

## 最新の承認済み週次改善メモ

```markdown
Updated: 2026-10-04

- 1秒目は「場所 + 違和感」、3秒以内に「理由の方向性 + 今すること」を置く。
- タイトルで答えを出す動画は、本編の追加価値を冒頭で約束する。
- 保存CTAは、最終画面に再利用できる一文・確認項目が残る場合だけ使う。
- 「待合での違和感」と「具体物・具体部位」を次週も別テーマで検証する。
- 1動画1検査1判断を維持し、検査ごとに対応が分かれる説明は分割する。
```

## 使い方のコツ

- 依頼文にルールを長く書かない。
- テーマ、対象ノート、素材フォルダ、今進めたい工程だけを書く。
- 台本全文を毎回貼り直さず、承認済みノートや素材フォルダを指定する。
- 画像、音声、動画へ進む時は「何がOK済みか」を短く書く。
- 人物が出る時は、Character全文ではなく `_character_quickref.md` と `_patient_clothing_index.md` を優先する。
- 投稿情報登録と分析・解析のコピペ欄は、運用に必要なので消さない。
- 台本確認で冒頭・保存・CTAを見る時は、最新の週次改善メモも確認させる。
- 次候補を出す時は、既存投稿・予約済み投稿と被らないかを先に確認させる。
- Claudeへ共有する時は、Claudeがローカルフォルダを見られない前提で、必要な既存タイトル一覧と週次改善点をプロンプト本文に直接貼る。
- テロップで重要語だけ色を変える時は、生成前に「強調語だけが別セグメントか」を確認させる。`any(key in part for key in highlights)` のような包含判定だと、語を含む文節全体が青になる。
- 修正版のテロップや画像は、前回フォルダに混ぜず日付つきの専用フォルダに出力させる。

Get-Process python, ffmpeg -ErrorAction SilentlyContinue | Stop-Process -Force
```

Get-Process | Where-Object { $_.ProcessName -match 'VOICEVOX|run|python|ffmpeg' } | Stop-Process -Force
